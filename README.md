# FireSync: MODIS-VIIRS Wildfire & Thermal Anomaly Analysis Prototype

FireSync is a Python portfolio prototype for exploring active-fire point detections and experimental cross-sensor matching. It provides two separate workflows:

- A Streamlit dashboard using deterministic **synthetic sample detections**. No key or NASA data download is needed. Its charts are not output from the matching algorithm.
- A command-line workflow that requests MODIS and Suomi-NPP VIIRS detection CSVs from NASA FIRMS, matches points, and writes a local Folium HTML map. A valid FIRMS key is required. Successful live ingestion has not been demonstrated in this review.

This repository does not establish participation, submission, acceptance, or awards in any competition year. It is maintained here as a portfolio project. It does not issue fire-spread alerts or predict fire perimeters.

## Run the synthetic dashboard

Python 3.12 is the reviewed environment. From this directory:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m streamlit run app.py --server.address 127.0.0.1
```

Open the local URL printed by Streamlit. A localhost URL is not a public hosted demo. Map basemaps may require internet access; the sample detections are generated locally. No public deployment or recorded demo is verified. [Portfolio presentation](docs/pitch_deck.md)

## Optional FIRMS workflow

Obtain a personal MAP_KEY from the NASA FIRMS service. Set `FIRMS_API_KEY` in your local environment or an untracked `.env` file, then run:

```powershell
.venv\Scripts\python main.py
```

Do not publish the key or share URLs containing it. The example requests the latest five days for a fixed Western US bounding box, from `MODIS_NRT` and `VIIRS_SNPP_NRT`. It runs once; it has no scheduler or automatic refresh. `download_firms` also accepts `VIIRS_NOAA20_NRT`, but the example does not call it. Raw data and processed output directories are created when writing files. The map is saved to `data/processed/fire_map.html`.

This workflow uses FIRMS point CSVs, not direct MOD14/MYD14 swath ingestion. Live response availability and product versions must be recorded in a separate run log before claiming demonstrated real-data results.

## Matching method and limits

- Default eligibility: geodesic distance on WGS84 at most 500 m and acquisition-time difference at most 30 minutes, in UTC.
- Eligible pairs are sorted by distance, time difference and input row positions. A greedy one-to-one selection uses each detection at most once. This is not an optimal assignment or a guarantee that points represent the same physical fire.
- Unmatched points from both sensors are retained. Matched location and time use MODIS; unmatched FRP is unchanged.
- Matched FRP is `(FRP_MODIS + 7 * FRP_VIIRS) / 8`. These are inherited experimental fixed weights, **not** measured confidence weights, a validated calibration, or a claim of improved accuracy. Source confidence values are retained.
- FIRMS distributes near-real-time products. Their delivery time is not the end-to-end latency of this application.
- VIIRS active-fire products have nominal 375 m resolution; MODIS fire products have nominal 1 km resolution. These values do not establish fused-output accuracy, fire size, or perimeter resolution.
- No fire-spread model, operational alerting, dispatch validation, or measured reduction in false alarms is included. Pair enumeration is suitable for small examples and has not been benchmarked for large regional workloads.

## Validate locally

```powershell
.venv\Scripts\python -m pytest tests -q
```

Tests cover matching, retained unmatched points, no reuse, geodesic thresholds, empty maps, CSV validation, mocked FIRMS downloads and Streamlit startup/filtering. Mocked requests and synthetic fixtures do not demonstrate a successful live NASA download. See `docs/validation.md` for the actual reviewed run and its limits.

## Data and method references

- NASA FIRMS service and NRT description: `https://firms.modaps.eosdis.nasa.gov/`
- FIRMS Area API contract (documented day range 1-5): `https://firms.modaps.eosdis.nasa.gov/api/area/`
- MODIS products, including FIRMS MCD14DL: `https://modaps.modaps.eosdis.nasa.gov/services/about/products/c61-nrt/index.html`
- VIIRS 375 m active-fire product: `https://modaps.modaps.eosdis.nasa.gov/services/about/products/viirs-land-c2-nrt/vj114imgtdl_nrt.html`
- Geodesic method library: `https://pyproj4.github.io/pyproj/stable/api/geod.html`

The synthetic dataset is generated by `src/sample_data.py` with seed 42. Its dates are illustrative, not evidence of observed fires or project participation in that year. Real datasets must be attributed separately with source, product/version, retrieval time and acquisition period when used.
